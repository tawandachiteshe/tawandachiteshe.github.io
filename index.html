Multi-tenant SaaS · Go + React

Newsletter platform as a service

Hosted email marketing built on a multi-tenant fork of Listmonk. Customers sign up, create a workspace and start sending without anyone setting up servers for them.

  • Moved the architecture from one pod per tenant to one shared fork scoped by Host header. Adding a tenant is now a database row, not a deployment.
  • Provisioning goes through the fork's Operator API and Postmark's Account API, so every tenant gets its own sending server.
  • Custom domains, metered billing with pay-as-you-go add-ons, invoices, and a background worker that suspends lapsed accounts.
  • Swagger docs generated from the code, versioned migrations, and one make check gate (fmt, vet, build, test).

Desktop · Rust + Tauri 2

Offline-first point of sale

A till app for retail. It keeps selling with no internet and syncs once the connection is back.

  • Rust handles everything that must be correct: the typed GraphQL client, SQLite, sale arithmetic that matches the server exactly, and ESC/POS receipts.
  • Sales upload in idempotent batches with retries. If the server rejects a batch, it's resent one sale at a time so nothing is lost.
  • Finds network printers on the LAN and prints over USB on Linux and Windows. Supports a customer display on a second monitor.

How I work remotely

  • I write things down. Every project starts with a design doc and keeps a docs/ folder explaining why decisions were made, so nobody has to wait for a meeting to find out.
  • Small changes, real checks. Formatting, linting and tests have to pass before I call something done. I keep pull requests small enough to review over coffee.
  • Typed boundaries. I generate API clients from schemas instead of writing payloads by hand, and model errors explicitly. This removes a lot of the bugs that come up in code review.
  • Built for bad networks. I build in places where power and connectivity drop out, so I design for offline use and retries from the start.
